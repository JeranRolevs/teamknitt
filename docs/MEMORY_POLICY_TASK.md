# Authored memory-policy research adapter

memory_policy.v1 adds executable retention policies to the configurable orchestration.
Create a self-contained task with teamknitt init /new/workspace --template memory.
The generator, evaluator, sandbox worker, baseline sources and public protocols ship in the
[example](../examples/memory_retention/README.md). Private seed panels are generated locally.

The study runner dispatches by explicit adapter kind. A trusted supervisor owns labels,
future observations, private seeds and measurements. Only a separate OS-sandboxed interpreter
executes submitted source. The source is attributed to the actual configured generation
model and actor, with its SHA-256 recorded.

The constrained API is select(bank, ages, new, t, capacity, aux). It returns retained indices
and up to 32 finite auxiliary numbers. The namespace resets each call. Current input is
scored against old memory before update. Source, state, CPU/time and process RSS limits are
separate checks. Compression and scorer changes require another contract.

AST validation enforces the API; the OS sandbox supplies the execution boundary.
No file writes, hidden-file reads, networking or forks are permitted. The macOS adapter
fails closed elsewhere and must pass native qualification before a research run.

Calibration, scored development and confirmation use disjoint panels. The policy stays fixed
for confirmation; a fresh event-free confirmation-calibration panel refits its threshold.
Scored confirmation runs never fit that threshold or return to the acting agents.
One false-alarm unit is any alarm during an independent finite-horizon benign run.

The smoke profile checks operation with small counts. The full profile is a separate harder
study. Actual authoring/instrument smoke checks do not establish novelty, a guaranteed alarm
rate or organizational superiority. The user selects and compares lab styles and sharing;
candidate refinement never changes those settings automatically.
