# teamknitt 0.7.0 — multiple native teams

- 1–8 independent native teams for one shared task, with separate members (1–16), roles,
  topology, sharing, provider/model settings and local budgets.
- Explicit collection-wide request, wall-time and concurrency caps; no multiplication by
  team count, automatic allocation, winner selection or merge.
- Inter-team communication defaults to none. Configured directed links can carry bounded
  designated-member summaries/contributions from completed prior waves. Separate connected
  components progress independently; raw private artifacts/styles are not exported directly.
- Draft-first configuration, route changes, explicit native cloning/removal and scheduled
  disturbances, with private backups, shared run lock and concurrent-edit checks.
- Native per-team feedback/pause/resume/stop controls retain the shared deadline and counters.
  Feedback uses the verified collection workspace and selected member scope.
- Collection overview and detailed per-team views, read-only metadata/draft APIs, portable
  offline snapshots and direct headings. No browser execution, queue write or arbitrary-file API.
- External style URLs are references only, not imported foreign skills, prompts, templates,
  configurations, code or runtimes. Actual style context must be explicitly local user-authored
  text. Repeated references can belong to distinct teams; no faithful-protocol claim is made.
- Initial collection execution supports bounded text/code proposals, not delegated/scientific
  workflows, unrestricted coding, verified tests or automatic repository merging. Unsupported
  settings fail before requests rather than being silently changed. Existing single-team and
  advanced engine workflows remain available.

No paid provider calls for setup, plans, tests, demos, views, diagrams or packaging. Based on
Labtune; author Goran Mitevski / copyright/licensor Pioneertown B.V. The unchanged Labtune
Academic Research License 2.0 still governs all use; functionality does not broaden eligibility.

# teamknitt 0.6.0 — research-informed, human-directed intervention

- Integrates **“Background: Research and Theory on Human Teams — 9 Nov 2026 · @Goran”**
  in `docs/TEAM_RESEARCH.md`, the offline `theory` catalogue, reports, starters and viewer.
- Separates **Non-system/System explanatory locus**, **compositional/compilational emergence**
  and **process/state/outcome** records. Historical Standard/Complexity presentation aliases
  still work without rewriting saved configurations or records. IPO/IMOI includes feedback,
  states and conditional relations—not a claim that conventional models are simply linear.
- Six focused views include differentiated/compilational **transactive memory** and explicitly
  grounded **interactive team cognition & coordination**. Configured expertise directories are
  not validated transactive-memory systems. Psychological states remain unmeasured; dynamics
  principles motivate questions without implemented recurrence, entropy or synchrony estimators.
- Frames the workflow as **configure → set tasks → follow work → intervene**. The intervention
  desk distinguishes conditions/configuration, planned disturbances, live controls and human review.
- Adds draft-first, explicit-apply `intervene` requests: bounded private targeted feedback and
  dependency-wave-boundary pause/resume/stop, with run/configuration bindings and private audit
  receipts. Current-wave work may finish. Pause retains the lock, deadline and counters;
  resume resets no limits; stop is terminal and preserves partial output without completed-study
  confirmation. Feedback grants no tool/source permissions or engine-setting changes.
- Adds `schedule` for explicit future-run actor, representation or directed-link gaps, with
  compiler validation, private backup and the shared apply lock. It is not model-weight
  training, a human-study replication, evidence of AI adaptation or an active-run config edit.
- Queued, applied, context-assembled, understood and improved remain distinct. Metadata excludes
  feedback text. The browser still cannot apply changes, queue controls, read arbitrary files,
  start execution or make model calls. No new multi-user or cryptographic audit guarantee.

The standalone `teamknitt.engine`, all 14 topology presets at 1–16 members, explicit model/
communication/tool/statistical/delegation/budget choices, separate-context probes and read-only
historical compatibility remain. Bayesian/probabilistic analysis and prior workflows remain
unavailable; unsupported selections fail, never silently convert. No automated organizational
improvement, silent model selection or budget increase is added. Advanced engine workflows do
not acquire main-run control hooks implicitly.
